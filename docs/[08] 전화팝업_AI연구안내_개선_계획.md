# [08] 전화 팝업 · AI 연구 안내 개선 계획

> 작성일: 2026-10-22 · 브랜치 기준: `dev` · 상태: 구현 완료 (기술 내용은 [09] AI최종모델.md 기준, 체험 사이트는 `/age-lab` 목업만)

## 목표

1. **공식 제보·신고 전화 팝업**: 내용 양에 맞는 비율로 줄이고, 모바일에서는 엄지로 누르기 쉬운 형태로 다시 디자인한다
2. **AI 연구 안내**: 예시 인물 이미지와 애니메이션으로 "얼굴 검출 → 특징점 추출 → 나이 변환 → 헤어스타일 변형" 과정을 **눈으로 따라가며** 이해하게 한다
3. **신뢰**: 사진이 외부 AI 서비스로 나가지 않는다는 점, AI 결과는 실제 얼굴 재현이 아닌 **생성된 참고 이미지**라는 점, 결과를 어떻게 **검증**하는지를 크게 강조한다

## 1. 전화 팝업 개선

### 지금 문제

- `Modal` 기본 폭이 `max-w-170`(680px)이라 항목 3개짜리 팝업이 가로로 휑하다
- 모바일에서 화면 가운데 뜨는 카드라 엄지가 닿기 멀고, 긴 번호(02-777-0182)와 설명이 한 줄에서 서로 밀린다
- 112(긴급)와 나머지 번호의 위계가 색 말고는 차이가 없다

### 디자인

```
데스크톱·태블릿 (폭 420px, 가운데)          모바일 (아래에서 올라오는 시트)
┌──────────────────────────────┐          ┌────────────────────────┐
│ 공식 제보·신고 전화         ✕ │          │        ───             │ ← 손잡이
│ 상황에 맞는 번호를 누르면…    │          │ 공식 제보·신고 전화   ✕ │
│ ┌──────────────────────────┐ │          │ ┌────────────────────┐ │
│ │ 🚨 지금 위급해요     112 │ │ ← 빨강   │ │ 🚨 지금 위급해요    │ │
│ │ 눈앞에 있거나 위험할 때   │ │   크게   │ │ 112           [전화]│ │
│ └──────────────────────────┘ │          │ └────────────────────┘ │
│ ┌────────────┐┌────────────┐ │          │ ┌────────────────────┐ │
│ │ 182        ││02-777-0182 │ │          │ │ 182  실종아동 제보   │ │
│ │ 실종아동    ││실종아동     │ │          │ ├────────────────────┤ │
│ │ 제보·상담   ││전문기관     │ │          │ │ 02-777-0182 전문기관 │ │
│ └────────────┘└────────────┘ │          │ └────────────────────┘ │
│ 안전Dream ↗ · 전문기관 ↗      │          │ 안전Dream ↗  자세히 →  │
│                  제보 방법 → │          │ (safe-area 여백)        │
└──────────────────────────────┘          └────────────────────────┘
```

- **위계**: 112는 전체 폭 카드로 크게, 182·전문기관은 2열 카드(데스크톱) / 목록(모바일)
- **번호 표기**: 번호가 주인공. 숫자 28px 이상, `tabular-nums`, 줄바꿈 금지(`whitespace-nowrap`)
- **터치 영역**: 항목 높이 최소 64px, 항목 간격 8px 이상
- **모바일 시트**: `max-sm`에서 화면 아래에 붙고, 위로 슬라이드되며 열림. `env(safe-area-inset-bottom)` 여백 포함
- **데스크톱 안내**: `tel:`이 안 되는 PC를 위해 "휴대전화로 걸어 주세요" 보조 문구 (포인터가 `fine`일 때만)
- **동작 줄이기**: `prefers-reduced-motion`이면 슬라이드 없이 바로 표시

### 구현

- `Modal`에 옵션 추가: `size="narrow"`(max-w 420px), `mobileSheet`(작은 화면에서 하단 시트)
- `ReportCallButton.tsx` 레이아웃 교체. 번호 데이터는 기존 `OFFICIAL_CALLS` 그대로, `tone: "urgent" | "default"` 필드만 추가
- 확인 폭: 320 / 375 / 768 / 1280px, 가로 모드 모바일(높이 360px)에서도 스크롤로 다 보이는지

## 2. AI 연구 안내 — 시각적 설명

### 전체 흐름 (위에서 아래로 스크롤)

| # | 섹션 | 큰 문구 (예시) | 시각 요소 |
| --- | --- | --- | --- |
| 1 | 히어로 | **AI는 얼굴을 복원하지 않습니다. 기억을 돕는 단서를 그립니다.** | 문구가 한 줄씩 떠오름 |
| 2 | 작동 과정 (스크롤 스토리) | 아래 4단계 | 예시 인물 사진 위 애니메이션 |
| 3 | 사진은 밖으로 나가지 않습니다 | **외부 AI 서비스로 사진을 보내지 않습니다** | 데이터 흐름 다이어그램 |
| 4 | 이렇게 검증합니다 | **AI 결과만으로 사람을 판단하지 않습니다** | 검증 단계 체크리스트 |
| 5 | AI 사용 원칙 · 할 수 있는 것/없는 것 | (기존 내용 유지, 글씨 키움) | 카드 |
| 6 | (선택) 연구 로드맵 | 아래 "확인이 필요한 내용" 참고 | 타임라인 |

### 2-1. 작동 과정 스크롤 스토리

데스크톱은 **왼쪽에 사진이 고정(sticky)** 되고 오른쪽 설명이 스크롤되면서 사진 위 애니메이션이 단계별로 바뀐다. 모바일은 단계마다 사진+설명이 한 묶음으로 세로 배치.

예시 인물: `MC-2008-0915` (생성 이미지로 만든 **가상 인물**. 화면에도 "가상 인물 예시" 표시)

| 단계 | 화면 애니메이션 | 설명 문구 (크게) |
| --- | --- | --- |
| ① 얼굴 찾기 | 사진 위를 스캔 라인이 위→아래로 훑고, 얼굴 둘레에 박스가 그려짐 | 사진에서 얼굴 위치를 먼저 찾아요 |
| ② 특징점 추출 | 눈·눈썹·코·입·턱선에 점이 하나씩 찍히고(약 40~70개), 점이 선으로 이어짐. "눈 사이 거리", "얼굴 세로:가로 비율" 같은 측정선과 수치 라벨 표시 | 눈·코·입의 위치와 얼굴 비율을 숫자로 읽어요 |
| ③ 나이 변환 | 나이 숫자가 3 → 21로 올라가며 어린 사진이 성인 사진으로 서서히 바뀜. 턱선·얼굴 길이 윤곽선이 함께 늘어남. 사용자가 직접 끌어 비교하는 **전·후 슬라이더** 제공 | 성장 과정의 골격 변화를 반영해 지금 나이의 얼굴을 그려요 |
| ④ 스타일 변형 | 머리 영역이 하이라이트된 뒤 기본 → 웨이브 → 단발로 순서대로 바뀜 (탭으로 직접 선택 가능) | 머리 모양처럼 시간이 지나며 달라지는 부분을 여러 모습으로 보여줘요 |
| ⑤ 결과 표시 | 결과 사진에 "AI 생성 · 참고용" 라벨이 찍힘 | 결과는 실제 얼굴이 아니라 AI가 만든 참고 이미지예요 |

- 특징점 좌표는 예시 사진에 맞춰 **미리 정해 둔 시연용 좌표**(`lib/aiDemo.ts`)로 그린다. 실제 브라우저에서 얼굴 인식을 돌리지 않으므로, 화면에 "작동 방식을 보여주기 위한 시연" 문구를 둔다
- SVG 오버레이(viewBox 543×724, 사진 원본 비율)로 그려서 어느 폭에서도 사진과 점이 어긋나지 않게 한다
- 애니메이션은 화면에 들어올 때 시작(`useInView`), 다시 보기 버튼 제공
- `prefers-reduced-motion`이면 각 단계의 **완성된 장면**만 정지 화면으로 보여준다
- 스크린리더용으로 각 단계 장면을 글로 설명(`figcaption`)

### 2-2. "사진은 밖으로 나가지 않습니다" 섹션

```
 [ 사진 ] ──▶ [ 🔒 FindUs 관리 서버 ] ──▶ [ AI 참고 이미지 ]
                      │
                      ╳──▶ [ 외부 생성형 AI 서비스 ]   ← 끊긴 선 + 취소 표시
```

- 큰 문구: **"사진은 밖으로 나가지 않습니다."**
- 체크 목록 (⚠️ 아래 "확인이 필요한 내용" 1번 확인 후 확정):
  - 외부 생성형 AI 서비스(ChatGPT 등)에 사진을 보내지 않습니다
  - FindUs가 관리하는 서버 안에서만 처리합니다
  - 실제 실종아동의 사진은 AI 학습에 쓰지 않습니다 (기존 원칙)
  - 결과 이미지에는 항상 "AI 생성" 표시가 붙습니다
- 애니메이션: 사진 아이콘이 선을 따라 서버로 이동, 외부로 가는 선은 그려지다가 끊김

### 2-3. "이렇게 검증합니다" 섹션

- 큰 문구: **"AI 결과만으로 사람을 판단하지 않습니다."**
- 단계: AI 예상 모습 생성 → 원본 사진·특징과 함께 표시 → 제보는 공식 기관(182·112)으로 → **신원 확인은 DNA 검사 등 공식 절차로만**
- (⚠️ 확인 필요) 결과 품질을 어떻게 평가하는지 실제 방법이 있다면 추가: 예) 같은 사람의 어린 시절·성인 사진이 공개된 데이터로 비교, 전문가 검토 등

### 2-4. 글씨·애니메이션 기준

- 섹션 큰 문구: 데스크톱 40~48px / 모바일 28~32px, 굵게, 줄바꿈은 `break-keep`
- 본문: 17~18px / 모바일 16px
- 애니메이션은 "의미 있는 곳에만": 문구 등장(fade-up), 특징점 찍기, 나이 숫자 카운트, 사진 전환, 데이터 흐름. 장식용 반복 애니메이션은 넣지 않는다
- 기존 `useInView`, `useReducedMotion`(`lib/useMotion.ts`) 재사용

## 3. 확인이 필요한 내용 (중요)

이 페이지는 **신뢰**를 주는 페이지라서, 사실이 아닌 문장이 하나라도 있으면 오히려 역효과가 납니다. 아래는 구현 전에 사실 여부를 확인해야 합니다.

### ① "회사 서버 안에서 돌리고 외부로 나가지 않는다"

- **실제로 그렇다면 적극 강조할 가치가 큼** → 2-2 섹션 그대로 진행
- 지금 사이트에는 "AI 예상 모습은 준비 중"이라고 나와 있음. 아직 운영 전이라면 "처리합니다"가 아니라 **"처리하도록 설계하고 있습니다"** 로 써야 함
- 클라우드(AWS 등)를 쓴다면 "회사 서버"보다 **"FindUs가 직접 관리하는 서버"** 가 정확한 표현

### ② "재미용 나이 변환 사이트를 운영하고 강화학습으로 계속 학습 중"

**지금 형태로는 넣지 않는 것을 추천합니다.**

- **사실 여부**: 실제로 운영·학습 중이 아니라면 "진행 중"이라고 쓸 수 없음
- **신뢰와 충돌**: 바로 위에서 "사진은 밖으로 안 나간다", "학습에 쓰지 않는다"고 강조한 페이지에 "다른 사이트에서 모은 얼굴로 학습한다"가 붙으면, 읽는 사람은 "내 사진도 학습에 쓰이나?"부터 떠올림
- **개인정보**: 얼굴 사진을 학습에 쓰려면 개인정보 보호법상 **별도의 명시적 동의**가 필요하고, 얼굴 특징 정보는 민감하게 다뤄지는 정보라 보관·파기 기준도 공개해야 함
- **용어**: 사용자 사진으로 모델을 계속 개선하는 방식은 보통 "강화학습"이 아니라 **미세조정(fine-tuning)** 또는 **사용자 피드백 기반 개선**에 가까움. 틀린 용어는 전문성을 깎음

**대신 이렇게 넣는 것을 추천합니다** (실제 계획이 있을 때만):

> **연구 로드맵 (예정)**
> 동의를 받은 데이터와 전문가 검토로 결과 품질을 계속 개선할 계획입니다.
> 실제 실종아동의 사진은 학습에 쓰지 않습니다.

### ③ 그 밖에 넣으면 좋은 것 (추천)

- **결과 이미지에 항상 "AI 생성" 표시**: 공유·캡처되어 퍼져도 실제 사진으로 오해되지 않게
- **보관·삭제 기준**: 처리한 사진을 언제 지우는지 (예: 처리 후 즉시 삭제)
- **한계 사례 명시**: 영유아(만 3세 미만) 사진, 옆모습, 흐린 사진은 정확도가 크게 떨어진다는 안내
- **문의 창구**: AI 결과에 대한 이의·삭제 요청 방법
